# StudyBuddy-demo og implementeringsplan

## 2026-11-11 kl. 18:41 — Fredrik

### Oppgave
Utfør samlet arkitekturgjennomgang, utviklingsoppgaver, sprintplan og første kjørbare demo etter studentens «kjør disse punktene». Studenten avslutter deretter dagens sesjon og ber om commit-/pushstatus.

### Plan
- Ferdigstill eksisterende arkitektur og samkjør PRD/UX; kontroller med uavhengige gjennomlesere.
- Lag [epics og stories](../../.docs/planning-artifacts/epics.md), [implementeringsklarhet](../../.docs/planning-artifacts/implementation-readiness.md) og sprintstatus.
- Bygg og kontroller [Story 1.1](../../.docs/implementation-artifacts/spec-1-1-run-the-four-part-study-demo.md) med API-/nettlesertester og uavhengig kodegjennomgang.

### Resultat
Arkitektur, PRD og UX er ferdigstilt som planleggingsgrunnlag; linter 0 funn. Uavhengig krav-/teknologi-/adversariell kontroll og etterrettinger er dokumentert. Fire epics og 14 stories finnes; sprintfilen validerer uten problemer. Epic 1 er under arbeid, Story 1.1 er `review` for studentens gjennomgang; byggespesifikasjonen er `done` etter implementering og verifisering.

FastAPI-demoen har faktisk API og godkjent HTML/CSS/JavaScript-layout med fast syntetisk kilde, alle fire læringsdeler, skjulte svar/referanser, separate øvingsposisjoner, fanebytte, materialpanel, nullstilling og retry. Egen tekst/PDF, ekte KI, konto og varig lagring er ikke implementert. Demoen er tydelig merket og avviser vilkårlig input. Installasjon fra låsefil bestod. 30 API-/kontrakttester og 11 faktiske Edge-nettleserscenarier bestod etter rettinger, inkludert 15-sekunders tidsavbrudd, oppstartsfeil, semantisk ugyldige svar, forsinkede svar etter reset, tastatur og 320/390/480 piksler + 200 % layoutzoom. Skjermbilder ble inspisert. TestClient/httpx gir en upstream deprekasjonsadvarsel uten testfeil; full manuell skjermleser-/WCAG-kontroll er ikke gjennomført.

Kodegjennomgangen førte til tidsavbrudd, strengere validering og nye feil-/oppstartstester. Full-diff-kontrollen presiserte også serverstyrt oppheving av genereringskvitteringer og gjenopptak av allerede innrømmet eksplisitt lagring etter restart/ny innlogging. Dette er regler for senere live-implementering, ikke funksjoner demoen beviser. Refleksjonsgrunnlag og README er oppdatert.

Arbeidet er lokalt committet i `11e89f4296835b9c67028e0112f38706a226c0a3` (`feat: add runnable Study Buddy demo and implementation plan`). Etter studentens eksplisitte «push» ble dagens seks lokale commits pushet til GitHub (`main`: `13e65fe..6621ae1`). Push lyktes, og `main` var synkronisert med `origin/main` ved kontroll. Denne loggoppdateringen inngår også i den autoriserte pushen. Lokal demo startet på `http://127.0.0.1:8000`; README beskriver oppstart neste gang. Ingen skyressurser, betalte tjenester eller publisering opprettet.

### Åpne punkter
- Studenten gjennomgår Story 1.1-demoen; deretter er neste byggeoppgave Story 1.2, PDF-eksperiment med fysiske sidenumre og ressursgrenser.
- Resten av live-arbeidet følger backloggen: innlogging, egne kilder/KI, privat lagring og flere enheter. Modell/API/budsjett og hosting/e-post/region/backup må avklares før sine milepæler.
- Full manuell skjermleser-/native zoom-/WCAG-kontroll og faktisk live sikkerhets-/lagringstest gjenstår før appakseptanse.
- Bekreft faktisk innleveringsdato før endelig leveranseplan; datoene i planen er foreløpige.
